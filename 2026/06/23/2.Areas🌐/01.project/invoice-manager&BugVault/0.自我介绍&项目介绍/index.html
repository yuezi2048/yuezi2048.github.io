面试官你好，我是xxx，xxx软件工程硕士在读，主要研究方向是多模态推荐，但工程重心放在Agent系统开发上。

最近主要做了两个项目。

第一个是BugVault，一个基于MCP协议的AI编程记忆增强服务。

AI编程工具最大的痛点是跨会话记忆断层——昨天刚修好的Bug，今天换个会话又要重新排查一遍。我针对这个问题，搭建了一套本地离线的RAG系统：把历史Bug和解决方案经过父子分块处理后向量化，存入LanceDB。检索时走双路召回，向量匹配语义、BM25匹配报错关键词，再通过RRF融合和Cross-Encoder精排，返回最相关的历史经验。整个系统通过自研的MCP服务端暴露5个工具，Claude Code和Cursor可以直接调用，数据不出本地。基于120条离线评测集的验证，已归档问题的重复排查耗时降低了70%以上。

第二个是Invoice Manager，一个发票管理的AI Agent系统，校企合作项目，已交付企业试用。

我在这个项目中负责整体架构设计，以及前后端和Agent子系统的搭建。Agent层面，我设计了一个四状态的AgentLoop——BUILD、RUN、CONFIRM、RESPOND，注册了8个业务工具：5个查询类、3个资金操作类。核心要解决两个问题：一是资金操作的安全校验，资金类工具不会直接执行，而是先让LLM生成操作摘要，等待用户60秒内人工确认后才真正调用后端接口；二是权限透传与隔离，Agent通过Token透传调用Java后端，用户的RBAC权限在Java层统一校验，后端业务代码完全感知不到Agent的存在。

最近在百万级测试数据下做了一轮索引优化，通过EXPLAIN分析慢查询、删除冗余索引、调整复合索引字段顺序，把查询响应从20秒优化到200ms以内。

技术栈方面，我主要用Python和Java，对Agent工程化和RAG落地比较熟悉。以上就是我的基本情况。

面试官你好，我是xxx，xxx软件工程硕士在读。如果用一句话介绍我自己——我是一个懂Agent技术落地、同时非常在意产品价值的人。

最近做了两个项目，分别对应Agent应用的两个核心命题：记忆与安全。

第一个是BugVault，基于MCP协议的AI编程记忆增强服务。

先说它的价值：让AI编程助手拥有了长期记忆，已归档问题的重复排查耗时降低了70%以上。具体实现上，我针对”错误栈”这种特殊语义做了专门RAG优化——双路召回+Cross-Encoder精排，通过自研MCP服务端暴露5个工具，Claude Code和Cursor可以零侵入接入，数据不出本地。

第二个是Invoice Manager，发票管理AI Agent系统，校企合作项目，已交付企业稳定运行4个月。

这个项目的核心命题是：让AI能做事，但不允许它做错事。 我设计了8个业务工具，资金操作类强制走”人工确认”流程，上线至今零生产事故。

做完这两个项目之后我一直在想一个问题：技术验证跑通了，但怎么让更多普通人真的用上它？

BugVault的评测数据很好看，但它的形态是一个MCP服务端，只有开发者能用。Invoice Manager上线了，但用户的反馈渠道和迭代机制是我后期才加上去的。我发现自己最有成就感的时候，不是模型精度调上去的那一刻，而是看到用户真的在用、真的解决了问题的那一刻。

所以比起纯技术研究，我更想做”把技术变成产品“这件事。携程这个岗位正好切中我的兴趣点——Agent + 内容业务场景，需要有人既懂技术边界，又愿意深入业务做产品化落地。

我觉得这就是我想走的方向。以上是我的基本情况，谢谢。

invoice-manager

  • 针对财务人员发票系统步骤繁琐且重复的问题，我在原先业务系统基础上加入了AI助手，通过自然语言就可以快速办业务
  • 独立设计了 Agent子系统的状态机架构 + 工具注册体系，Agent通过内部Token透传与后端松耦合，新增工具半小时就可以快速实现原型，无须改造原有后端
  • 最大的挑战：
    • 如何在原有业务系统集成Agent？
      • 我选择了把Agent做成独立的Python服务，通过REST API调用后端，凭证透穿到Agent层，每次调用接口时带上该凭证，后端正常鉴权，感知不到Agent存在
      • 优势是：后续每次开发新工具（比如后续引入OCR发票识别等功能），不需要重新部署后端，业务零风险
    • 资金的敏感操作？
      • 我的想法是这种需要让人类背锅的业务，必须有人工介入，所以有了中断-确认机制
      • AI会生成行动操作摘要——用户确认——如果60s不确认自动取消
      • 保证每笔操作都经过人工审核
      • 这是目前MVP的一个原型，后续我还有优化想法，就是会将AI的操作加入到审核队列中，等待管理员逐个审批通过，后续我们希望的效果就是，办业务只需要确认执行，不需要重复操作
    • 会话怎么持久化？
      • 我们知道记忆有多个场景，像情景记忆，长期记忆，短期记忆等，像我bugvault就是做的情景记忆，而这个发票管理项目实际上用不到长期记忆，所以只需要短期记忆，实际场景来说我只需要最近的筛选条件等
      • 所以最终的技术选型就是Redis配合本地内存的双重缓存机制，Redis挂了自动降级纯内存的兜底

每条 bullet 按 S-T-A-R 拆解，面试时按此结构口述。

BugVault — 基于 MCP 的 Agent 本地记忆增强服务

项目背景（一句话）

跨会话记忆断层、项目经验无法继承、已修 Bug 反复重现 → 基于 MCP 的记忆增强服务

Bullet 1：链路编排

要素 内容
S AI 编程工具没有标准化的记忆接口，Claude/Cursor 各用各的
T 设计一套即插即用的记忆层，不侵入 AI 工具本身
A Agent 拆解为决策层（Claude）与记忆层（BugVault），通过 MCP 协议严格隔离；5 个工具覆盖检索/保存/反思完整链路
R 兼容 Claude Code、Cursor 等主流 MCP 客户端，无需修改 AI 工具本身

Bullet 2：RAG 链路设计

要素 内容
S 单块向量方案里，长方案文本会稀释报错特征，搜具体堆栈时不准
T 确保报错特征精准匹配，同时保留语义匹配能力
A 父子分块表：父表存元数据，子表按 error_log / semantic 分块
A 检索端走语义向量 + 关键词全文双路召回 → RRF 融合 → Cross-Encoder 精排
A 全本地 CPU 运行，数据不出本地
R 默认零外部 API 调用，企业级数据安全合规；30+ 种技术栈智能过滤防止误中

Bullet 3：效果与质量

要素 内容
S 检索质量无法量化，bad case 归因靠感觉
T 建立可量化、可追踪的 RAG 评测体系
A 自建离线评测集（覆盖事实查询、跨文档综合、无答案三类场景）
A 两阶段评测：simple 快速打分 + claim-level CoT 逐条验证
A 双重熔断器：会话级配额 + JSON 异常捕获，评测崩溃不阻塞检索
R 已归档问题重复出现率降低 70%+，137 项自动化测试覆盖 96% 功能特性

Bullet 4：工作流编排

要素 内容
S 开发前不知历史坑，开发后不归档，经验随会话丢失
T 构建完整的开发前→开发后 Agent 工作流
A 基于 BugVault 编写 Hook 与 Skill：preflight 开发前自动查经验，postflight 开发后自动归档
R 沉淀 6 篇 ADR 文档，技术决策可追溯、可复用

Invoice Manager — SaaS 发票管理与 AI Agent 平台

项目背景（一句话）

校企合作真实商业项目，财务人员无需学系统，说话就能办业务。

Bullet 1：后端工程

要素 内容
S 企业级发票高并发、细粒度权限、微信端全流程操作需求
T 高性能后端架构，支撑企业日常全流程
A Spring Boot RESTful 服务，15 张核心业务表
A Sa-Token RBAC 四级权限（超管/财务/业务/普通）
A 集成微信公众平台，员工绑定后全流程操作
A 索引从 23 个精简至 14 个，基于覆盖索引 + 复合索引优化
R 百万级数据查询响应 10-200ms，降低写入开销同时保持查询性能

Bullet 2：Agent 子系统

要素 内容
S Agent 与 Java 后端紧耦合，每次加功能都要改后端发版，风险高
T 解耦 Agent 与后端，迭代不影响业务
A 注册 8 个业务工具（5 P0 查询 + 3 P1 资金操作），LLM 意图路由
A 内部 Token 认证透传，Agent 独立服务通过 HTTP 调用后端
A AgentLoop 设循环上限防止死循环，每次调用写入日志
R 新增一个工具平均 30 分钟内完成，无需后端发版，业务零风险

Bullet 3：会话记忆管理

要素 内容
S 会话丢失、重启丢上下文、用户需重复输入筛选条件
T 可靠持久化 + 降级兜底 + 减少重复输入
A Redis 双重缓存（内存热缓存 + Redis 持久层），30 分钟 TTL 自动续期
A 服务重启后会话与中断确认进度自动恢复
A Redis 不可用时降级为纯内存模式，不阻塞业务
A 查询时自动继承上一轮筛选条件（公司、日期、状态）
R 用户无感恢复，业务永不阻塞

Bullet 4：运营与反馈

要素 内容
S Agent 效果不可见，用户反馈无闭环，问题重复出现
T 建立可观测 + 可迭代的运营体系
A 搭建 Agent 运营看板（成功率、耗时分布、bad case 归因）
A 用户点赞/点踩自动归因→触发 Prompt/工具优化闭环
A 定时 Agent 自动执行月结对账与风险预警推送
R 已上线校企合作企业日常使用

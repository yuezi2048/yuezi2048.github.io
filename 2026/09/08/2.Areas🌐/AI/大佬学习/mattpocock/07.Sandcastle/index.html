07.Sandcastle

发表于2026-09-08|更新于2026-09-08|2.Areas🌐AI大佬学习mattpocock
|总字数:1k|阅读时长:3分钟|浏览量:

TypeScript 教育者 Matt Pocock 开源了 Sandcastle——一个 TypeScript 库，把 Claude Code、Codex 等 AI 编码 agent 编排进隔离的 Docker 沙箱，让它们自动认领 GitHub issue、实现功能、review 代码、合并回 main，全程 AFK（无人值守）运行。

看点：

  1. 为什么开 YOLO 模式会让 Claude 删掉你的 home 目录——以及沙箱怎么根治这个问题
  2. 一个 sandcastle.run 函数，怎么搭出「planner→implementer→reviewer→merger」的并行 agent 流水线
  3. 从 Docker 沙箱到对抗式 code review：让你真正拥有自己的 agent 编排流程，而不是被第三方服务绑架

关键内容：
· 问题根源：AFK agent 会不断发起权限请求；YOLO 模式有删目录、数据外泄等风险，沙箱是刚需
· Sandcastle：用 TypeScript 在隔离沙箱里编排 AI 编码 agent 的库
· 核心原语：sandcastle.run(agent, sandbox, prompt)，简单但能搭出复杂并行系统
· backlog 管理：用 GitHub issues + sandcastle 标签给 agent 派活
· 四种 agent 角色：planner（规划）、implementer（实现）、reviewer（审查）、merger（合并）
· 开箱模板：带 review 步骤的并行 planner
· 沙箱 provider：默认 Docker，也支持自定义实现
· 配置结构：.sandcastle 目录、Dockerfile、.env（Anthropic API key + GitHub token）
· Claude Skills 语法彩蛋：反引号前加感叹号，解析 prompt 时执行命令（如 git diff）
· 实战结果：agent 自动 scaffold 出一个 TypeScript 项目（Vitest + Commander + 类型检查 + CI）

来源：
· 原视频：https://www.youtube.com/watch?v=E5-QK3CDVQM
· 仓库：https://github.com/mattpocock/sandcastle
· npm 包：@ai-hero/sandcastle

00:00:00 开场：过去半年的目标是让编码 agent 完全 AFK 运行——并行跑、自动领任务
00:00:51 为什么沙箱是刚需：YOLO 模式会让 Claude 删 home 目录、企业担心数据外泄
00:01:21 现有方案（Docker Sandboxes 等）不满意，决定自己造：Sandcastle 登场

docker sandbox跑AFK问题太多，作者想要的是只需要通过TypeScript函数就能让Agent在沙箱里执行指定Prompt，但是市面上都在推销第三方服务。

那么就造了轮子：专门用于隔离沙箱编排AI编码的Agent

作者任何一个开源仓库里面都会有一个.sandcastle的目录，里面有main.mts文件，里面包含大量sandcastle.run小函数来搭建复杂的系统（多Agent并排，review代码merge进去）

00:03:00 .sandcastle 目录与 Dockerfile：装系统依赖、GitHub CLI、Claude Code
00:03:36 构建 Docker 镜像，配置 .env（Anthropic API key + GitHub token）
00:04:23 commit & push，创建第一个 issue：scaffold 一个 TypeScript 模板（Vitest + Commander + CI）
00:04:57 在 package.json 加 sandcastle 运行脚本

00:06:18 拆解 main.mts：planner→implementer→reviewer→merger 的完整流程，prompt 文件可自由编辑

思考参考：

恰恰相反，我知道他这个，本来想着用skill不就好了，为什么还要写typescript控制流程。 后来skill写完了明白了，每次dispatcher会话等待implementer会话，都会携带全量上下文，随便写一个dispatcher skill后果就是dispatcher会话比所有implementer会话加起来还要更加消耗token。 然后你就要仔细研究怎么写事件驱动而不是轮询驱动的dispatcher，然后就会发现各家coding agent有各家的限制，比如qoder就根本做不出来，只能轮询，codebuddy更是废物。我费劲用codex做出来了，测试下来依然只是降低token浪费，随着implementer会话越来越多，token消耗还是会越来越大。 最重要的是skill来实现dispatcher难以调试，总之全方位不如sandcastle一根毛

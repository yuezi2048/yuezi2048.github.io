19.SpringBoot3.x对比2.x

发表于2025-11-25|更新于2025-11-25|2.Areas🌐02.面经记录面试鸭SpringBoot
|总字数:1.4k|阅读时长:4分钟|浏览量:

  • JDK17支持：3.x要求JDK17最低版本，2.x兼容性更广（JDK8 11 17）

  • 包迁移：从 javax.* 变更为 jakarta.*，从JavaEE迁移到了Jakarta

  • 原生编译支持（GraalVM Native Image）：支持对Spring编译为本地可执行文件，减少启动时间 / 内存占用，特别适合微服务、云原生应用

  • 观察性改进（Observability）：将 Micrometer 和 Micrometer Tracing 深度集成，引入了更完善的分布式追踪、日志关联和性能指标收集，支持 OpenTelemetry 标准。Observability 使开发者能够更好地监控和分析应用的运行状况。

  • 安全性增强： 3.x增强了对 Spring Security 6 的支持，进一步强化了身份认证、授权和安全配置的能力，特别是对于 OAuth 2.1、OpenID Connect 等标准的支持更加完善。

  • 模块化和简化的依赖管理：pring Boot 3.x 对内部依赖进行了一些模块化调整，清理了一些不再使用或过时的库，优化了依赖管理，使得应用更加轻量和易于扩展。

从 Spring Boot 2.x 升级到 3.x，开发者需要注意以下几个方面：

  1. JDK 版本升级：确保项目已经使用 JDK 17 或更高版本。
  2. Jakarta EE 的包名迁移：所有 javax.* 包名需要迁移到 jakarta.*，包括所有与 Servlet、JPA、JMS 等相关的 API。
  3. 检查依赖的兼容性：某些老旧的库或依赖可能不再兼容 Spring Boot 3.x，建议升级到最新的依赖版本。
  4. 原生编译的适配：如果需要使用 GraalVM 原生镜像，需要确保代码和依赖与原生镜像兼容，某些反射、动态代理等特性可能需要进行适配。

扩展知识

Jakarta EE 的迁移

Spring Boot 3.x 迁移到了 Jakarta EE 9+，这是从 Java EE（javax 包）到 Jakarta EE（jakarta 包）的一个重大变动。几乎所有与 Servlet、JPA、JMS 等相关的 API 包名都从 javax.* 改为 jakarta.*。

GraalVM Native Image 支持

Spring Boot 3.x 对 GraalVM Native Image 的支持是一项重要的改进，Native Image 能够将 Java 应用编译成本地可执行文件，具有以下优势：

  • 快速启动时间：相比传统的 JVM，原生编译后的应用可以在毫秒级别启动，适合容器化和微服务场景。
  • 更低的内存占用：原生应用不需要 JVM，整体的内存占用更低。

Observability 与 Micrometer 的集成

Spring Boot 3.x 引入了增强的 Observability 特性，支持分布式追踪和日志关联。Observability 可以帮助开发者监控应用的整体性能，识别瓶颈，并及时调优。它集成了 Micrometer 和 OpenTelemetry，适用于现代分布式系统的监控需求。

常见的监控和追踪场景：

  • 请求链路追踪：通过 Micrometer Tracing 可以跟踪 HTTP 请求的完整链路，从接收到响应的每一步操作都可以被监控。
  • 性能指标监控：集成 Prometheus、Grafana 等监控平台，可以实时查看应用的性能指标，如 CPU 使用率、内存占用、请求响应时间等。

安全性与 Spring Security 6

Spring Boot 3.x 支持 Spring Security 6，这意味着对最新的安全标准（如 OAuth 2.1、OpenID Connect 1.0 等）的支持更加完善，并且在密码管理、令牌授权和认证流程上有了更安全和灵活的配置方式。

Spring Boot 3.x 的模块化和依赖管理

Spring Boot 3.x 进一步优化了依赖管理，清理了一些不再维护或支持的库。例如，某些老旧的日志框架、工具库在 Spring Boot 3.x 中被移除，转而使用更现代的解决方案。

此外，Spring Boot 3.x 对某些模块进行了拆分和独立管理，使得开发者可以根据项目需要灵活选择依赖，避免不必要的庞大依赖树。

迁移策略与兼容性

从 Spring Boot 2.x 升级到 3.x，开发者需要注意以下几个方面：

  1. JDK 版本升级：确保项目已经使用 JDK 17 或更高版本。
  2. Jakarta EE 的包名迁移：所有 javax.* 包名需要迁移到 jakarta.*，包括所有与 Servlet、JPA、JMS 等相关的 API。
  3. 检查依赖的兼容性：某些老旧的库或依赖可能不再兼容 Spring Boot 3.x，建议升级到最新的依赖版本。
  4. 原生编译的适配：如果需要使用 GraalVM 原生镜像，需要确保代码和依赖与原生镜像兼容，某些反射、动态代理等特性可能需要进行适配。

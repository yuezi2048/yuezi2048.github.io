设计链表

707. 设计链表

二刷修正：

坑点：

  • 删除时尾节点的更新情况有两种（cur == null || cur.next = = null），否则会在第47个测试点GG
  • index的判断实际上根据长度划分，在while循环退出后，划分为以下三种状态：
    • 超过链表长度的状态： i < index && cur == null
    • 恰好等于的状态：i == index && cur == null
    • 正常小于链表长度的状态：i == index && cur != null （else）
  • 在get的时候，需要判断当前cur是否为null

三刷：更加顺手了

  • 还是要务必注意尾节点的更新：删除、添加（包括头插、尾插、任意位置插入）
  • 删除尾节点是可以合并成cur.next判断的，不用单独加上null
  • 坑：任意位置插入时尾插时，必须判断index指针刚好遍历到链表长度，否则会出现64测试点G

四刷：注意尾节点的更新即可，注意链表的赋值

反转链表（双指针）

206. 反转链表

二刷后，我的pre是原来链表上的关系

二刷：递归改造，终止条件是到最后一个元素终止，每一次递归就是对单个元素进行一次指针“反转”操作

三刷：

迭代和递归都能写出来了，注意p和q的赋值顺序即可，要优先分配保留指针p，否则死循环

两两交换链表节点

24. 两两交换链表中的节点

给你一个链表，两两交换其中相邻的节点，并返回交换后链表的头节点。你必须在不修改节点内部的值的情况下完成本题（即，只能进行节点交换）。

二刷的时候没有考虑到头结点来巧妙地修改前两位（不影响后面节点的指针），我这里还是有点偏向喜欢考虑状态的方式分析

三刷：稍微卡我时间的依然是状态保留指针顺序，使用nxt保留即可，相比于前面的q，感觉更清楚，非常顺手的能表示出一个循环中的两两交换关系 + 后面节点为空/1个/2个的情况

四刷，加入头结点后就不需要额外判断了，非常简洁，没有元素或者一个元素直接break，没有元素就跳出

删除倒数第n个节点（双指针）

19. 删除链表的倒数第 N 个结点

给你一个链表，删除链表的倒数第 n 个结点，并且返回链表的头结点。

二刷：这题为了方便删除，要用虚拟节点 + pre保留指针

三刷，后面遇到测试样例的时候，才考虑到应该要虚拟节点，无非就得多判断一下即可，只需要额外考虑到最后删除第一个的情况即可

面试题 02.07. 链表相交

给你两个单链表的头节点 headA 和 headB ，请你找出并返回两个单链表相交的起始节点。如果两个链表没有交点，返回 null 。

环形链表Ⅱ（双指针）

142. 环形链表 II

给定一个链表的头节点 head ，返回链表开始入环的第一个节点。 如果链表无环，则返回 null。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。如果 pos 是 -1，则在该链表中没有环。注意：pos 不作为参数进行传递，仅仅是为了标识链表的实际情况。

不允许修改 链表。

二刷：快慢指针+循环+相遇的场景，得到隐藏公式，并明确x =(n - 1)(y + z) + z的含义，要理解为起始点和相交点的相遇点

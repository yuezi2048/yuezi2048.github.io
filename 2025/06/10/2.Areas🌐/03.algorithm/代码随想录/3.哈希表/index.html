三、哈希法

3.1 理论基础

哈希表

  • 哈希表：key是关键字，作为哈希表的索引下标，访问对应的元素value，在算法中常常用来空间换时间

当我们需要查询一个元素是否出现过，或者一个元素是否在集合里的时候，就要第一时间想到哈希法

  • 哈希函数：映射方式，通常会有取模操作

  • 哈希碰撞：如果映射到了一个位置，那么就出现了碰撞，解决方案：

    • 拉链法

    • 线性探测法

哈希存储结构

集合 java对应类 底层实现 是否有序 数值是否可以重复 能否更改数值 查询效率 增删效率
std::set TreeSet 红黑树 有序 否 否 O(log n) O(log n)
std::multiset Map<String, Integer> 红黑树 有序 是 否 O(logn) O(logn)
std::unordered_set HashSet 哈希表 无序 否 否 O(1) O(1)
映射 java对应类 底层实现 是否有序 数值是否可以重复 能否更改数值 查询效率 增删效率

std::unordered_map HashMap 哈希表 key无序 key不可重复 key不可修改 O(1) O(1)

3.2 数组（字母异位词）

242. 有效的字母异位词

给定两个字符串 s 和 t ，编写一个函数来判断 t 是否是 s 的 字母异位词。

二刷使用map复习一波写法，更加兼容 原题说的Unicode的情况

三刷：

在三刷的时候发现一个有趣的现象，无论是数组还是用hashMap，分开写for循环最终的用时会更好。

数组层面应该是CPU的缓存亲和性，HashMap可能是写到一起后冲突更频繁导致扩容的开销

另外Map的遍历方式不要忘，附上entrySet、和values的hashMap的遍历方式

相关题目

  • 383.赎金信(opens new window)

    • 本题使用map的空间消耗要比数组大一些的，因为map要维护红黑树或者哈希表，而且还要做哈希函数，是费时的！数据量大的话就能体现出来差别了。 所以数组更加简单直接有效！

    • 注意计数的数据类型，不是char[26]

  • 49.字母异位词分组(opens new window)

    • 涉及到的算法：字符哈希 + 数组集合
    • 学到了一个基于hash合并的思路：

      • 将满足条件的基于Hash Key（字母异位词满足同个字符哈希），放在一个集合中（List）

        • 对于字母异位词的key，也可以暴力地通过排序来表示，但是该操作时间复杂度会有一个mlogm的级别（m是每个字符串的最大长度），而使用哈希表后，单个操作只有O(1)的时间复杂度（1=26）

      • 最终展现出来的方式是：返回map中所有的值（map.values）

四刷：给出computeIfAbsent，forEach等高级操作，特别适合value是集合一类的操作，并给出key的O1哈希桶排序算法

  • 438.找到字符串中所有字母异位词

    • 涉及到的算法：字符哈希+滑动窗口（注意利用滑动窗口的特性来应用双指针）
    • 优化：因为涉及比较，可以利用该点，来比较滑动窗口和比较字符串中不同字符数量的差

    • 三刷：我想用滑动窗口，然后应当考虑到大的字符串比 子串短的情况，另外要注意是start == end也可以

    • class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> res = new ArrayList<>();
        int[] ch = new int[26];
        for (int i = 0; i < p.length(); i ++) ch[p.charAt(i) - 'a'] ++;
        for (int i = 0; i < s.length() && i < p.length(); i ++) ch[s.charAt(i) - 'a'] --;
        if (judege(ch)) res.add(0);

        int start = 1, end = p.length();
        while (start <= end && end < s.length()) {
            ch[s.charAt(start - 1) - 'a'] ++;
            ch[s.charAt(end) - 'a' ] --;
            if (judege(ch)) res.add(start);
            start ++;
            end ++;
        }
        return res;
    }

    private boolean judege(int[] ch) {
        for (int i = 0; i < ch.length; i ++) {
            if (ch[i] != 0) return false;
        }
        return true;
    }
}

五刷：反思了一下，还是使用while循环的模板了，固定区间应该用for循环会更好控制，四刷版本更简洁

3.4 unordered_map

两数之和

1. 两数之和

给定一个整数数组 nums 和一个整数目标值 target，请你在该数组中找出 和为目标值 target 的那 两个 整数，并返回它们的数组下标。

为什么想到哈希表

快速判断一个元素是否出现集合里的时候，就要考虑哈希法了

为什么不用数组和Set，想到用Map

  • 数组的大小是受限制的，而且如果元素很少，而哈希值太大会造成内存空间的浪费。
  • set是一个集合，里面放的元素只能是一个key
  • 因此只有map可以了，这道题目中并不需要key有序，选择std::unordered_map 效率更高

map存什么，k和v是什么

map是为了存储已经访问过的元素，key是元素，value是下标

三刷：我尝试进阶，不只有一组可能的结果下，找出一组数据中所有的两数之和集合结果，也许此时用hash并不是一个很好的方案，优先考虑双指针，参考三数之和

列表转二维数组转换结果：int[][] resArr = res.stream()
.map(list -> list.stream().mapToInt(Integer::intValue).toArray())
.toArray(int[][]::new);

要对已经处理的数字用Set避免重复配队，并且要判断是否是两个相同的数字

  • 如果是相同的数字，要避免和同一个自己重复
  • 如果不是，直接正常合并然后标记数字即可，用set后续就不会再处理了

四数相加Ⅱ

454. 四数相加 II

给你四个整数数组 nums1、nums2、nums3 和 nums4 ，数组长度都是 n ，请你计算有多少个元组 (i, j, k, l) 能满足：

  • 0 <= i, j, k, l < n
  • nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0

这题区别于**0015.三数之和 (opens new window)，0018.四数之和 (opens new window)**，为什么可以使用哈希法？

本题是四个独立的数组，不用考虑重复的四个元素相加等于0的情况（需要对相同方案去重，使用哈希会很麻烦）

所以依旧是可以通过哈希来记录元素在集合中的出现次数。

三刷：我用了两个hashmap然后汇总的方式，注意是组合计数，更方便的应该是在ma2遍历过程中就可以顺带记录答案了

三数之和（去重）

15. 三数之和

给你一个整数数组 nums ，判断是否存在三元组 [nums[i], nums[j], nums[k]] 满足 i != j、i != k 且 j != k ，同时还满足 nums[i] + nums[j] + nums[k] == 0 。请你返回所有和为 0 且不重复的三元组。

**注意：**答案中不可以包含重复的三元组。

使用双指针

二刷，思路顺了以后就很快了，主要是确定一个基点s，然后双指针l，r，要注意s的去重和双指针的去重（s和l保留重复的最左边的，r保留重复的最右边的即可），把去重的思路理清后，配合双指针，这题直接攻破！

  • 这题要注意排序的思路，双指针的题，有时候需要借助一些递增/递减关系的，例如这题的和为0的问题上
  • 一刷的时候，通过记录值num1 num2 num3（配合指针移动赋值），依次来达到复用目的，似乎看着比较清晰一些，算是一个值得借鉴的点
  • 我始终保持循环不变量（s<size-2，l<r），这样就再也没有死循环的问题了，解题速度会快了很多，精力可以放到更多的其他细节上

三刷：给出判重最简洁的写法（注意只需要在sum=0的时候判重即可）

四数之和

18. 四数之和

给你一个由 n 个整数组成的数组 nums ，和一个目标值 target 。请你找出并返回满足下述全部条件且不重复的四元组 [nums[a], nums[b], nums[c], nums[d]] （若两个四元组元素一一对应，则认为两个四元组重复）：

  • 0 <= a, b, c, d < n
  • a、b、c 和 d 互不相同
  • nums[a] + nums[b] + nums[c] + nums[d] == target

你可以按 任意顺序 返回答案 。

二刷记录

坑点：

  • 四个数字相加可能爆int，必须要用long，计算时要考虑自动类型转换的细节（java）

剪枝思路：

  • 最小和：当前数 + 后续连续的 n-1 个数（如四数之和中，p 的最小和是 p+p+1+p+2+p+3）；
  • 最大和：当前数 + 最后 n-1 个数（如四数之和中，p 的最大和是 p+size-3+size-2+size-1）；
  • 若最小和 > target → 直接 break（后续数更大，无需继续）；若最大和 < target → 直接 continue（当前数的所有组合都不满足）。
  • 利用排序特性，当 nums[l] ≥ 0 时，后续所有数都是非负的，若 nums[p]+nums[q]+nums[l] 已超过 target，加上更大的 nums[r] 必然超 target，直接终止双指针循环；

优化：

  • 这里可以看到用for循环，其实一开始外层两个循环我是用while循环的，但是发现每次continue前都要手动加上s1++等操作，用for循环可以规避这个问题，减少由于遗漏自增，导致耗费的排错时间

可以看到虽然理论时间复杂度没变，但是经过我的一套**“剪枝组合拳”后确实实际运行时间减少了一些，这题应该是代码随想录的哈希表章节毕业题目了（懂得一些题目不能用哈希表解决，要用双指针等其他思路本身，就是对哈希表的更进一层掌握呀~）**，go继续下一章的复习
